DSA Problem Solving / Pattern 01

Sliding Window
formula sheet.

Goal: never have to relearn this from scratch again.

Step 0: which type is this?

Ask: Does the window size stay constant, or does it change?

AnswerTypeSignal words
Constant, given as kFixed“subarray of size k”, “window of length k”
Changes from a conditionVariable“smallest/shortest subarray”, “longest substring”, “at most K distinct”

For a variable window, ask next: Am I minimizing or maximizing the window length?

AnswerFlavor
Find the shortest valid windowFlavor A
Find the longest valid windowFlavor B

Type 1: fixed-size window

The formula:

runningValue = runningValue - (value leaving at i-k) + (value entering at i)

The two-phase recipe:

  1. Build: loop from 0 to k - 1 and accumulate the first window. This is the only point where every element is processed individually.
  2. Slide: loop from k to n - 1. Each step is one update with the formula, then update the answer.
int windowValue = 0;
for (int i = 0; i < k; i++) {
    windowValue += /* contribution of nums[i] */;
}
int best = windowValue;

for (int i = k; i < nums.length; i++) {
    windowValue -= /* contribution of nums[i-k] */;
    windowValue += /* contribution of nums[i] */;
    best = Math.max(best, windowValue); // or Math.min
}

Contribution can be the number itself (sum/average), 1 for an even number, or 1 for a vowel. Window max/min does not fit this formula: use a monotonic deque.

Type 2, Flavor A: shrink while too much (minimize)

Use for the shortest window satisfying a condition, such as sum ≥ target.

for right in 0..n-1:
    expand window using nums[right]
    while (window is still valid / “too much”):
        best = min(best, right - left + 1)
        remove nums[left]
        left++
int left = 0, windowSum = 0, best = Integer.MAX_VALUE;
for (int right = 0; right < nums.length; right++) {
    windowSum += nums[right];
    while (windowSum >= target) {
        best = Math.min(best, right - left + 1);
        windowSum -= nums[left++];
    }
}
return best == Integer.MAX_VALUE ? 0 : best;

Memory hook: “Expand always. Shrink while good. Record before you shrink.”

Type 2, Flavor B: shrink until valid again (maximize)

Use for the longest window satisfying a condition, such as no repeating characters or at most K distinct characters.

for right in 0..n-1:
    expand window using s[right]
    while (window is INVALID):
        remove s[left]
        left++
    best = max(best, right - left + 1) // after valid again
int left = 0, best = 0;
Map<Character, Integer> count = new HashMap<>();
for (int right = 0; right < s.length(); right++) {
    char c = s.charAt(right);
    count.put(c, count.getOrDefault(c, 0) + 1);
    while (count.size() > k) {
        char lc = s.charAt(left++);
        count.put(lc, count.get(lc) - 1);
        if (count.get(lc) == 0) count.remove(lc);
    }
    best = Math.max(best, right - left + 1);
}

Memory hook: “Expand always. Shrink only when broken. Record after you fix it.”

The biggest gotcha

Flavor A: minimizeFlavor B: maximize
When to record?Inside the while loop, before/while shrinking.Outside the while loop, after shrinking ends.
Why?You need the smallest valid point.You need the largest valid point.

Mixing up this contrast is the common reason variable-window code appears almost correct but fails.
